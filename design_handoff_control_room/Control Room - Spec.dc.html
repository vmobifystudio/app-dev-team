Implementation spec

Control room design system

Every value below is a literal, implementable in styles.css as a custom property. Light mode. No web fonts, no icon library, no CSS framework — the icon set stays hand-authored inline SVG on currentColor.

Kind chips reuse the semantic palette by meaning, not by decoration: a question is unanswered (amber), an answer or decision resolves (green / accent), an escalation or blocker demands a human (red), an fyi and a handoff only inform (blue / neutral). Handoff is the one neutral chip — it moves work without judging it.

Columns are grid-template-columns: repeat(5, 254px) with a 14px gap, inside an overflow-x: auto wrapper — a fixed track, never flex-grow and never minmax(0, …), which lets every track shrink to nothing and squashes the cards instead of scrolling. 254 is not arbitrary: 5×254 + 4×14 = 1326px, which plus 48px of content padding and the 60px rail is 1434 — the widest the board can be and still fit a 1440px laptop with the sidebar collapsed. One column holding twenty tickets and four holding none looks the same width as an even spread, which is the common real shape at sprint start and sprint end. An empty column says so in words rather than rendering as a void.

Verdict bar — a section whose whole body is its verdict
CLEAR — every off role in the roster names why it is off. swept all 7 roster rows
CANNOT EVALUATE — docs/02-team-roster.md was not readable. swept nothing

Used where a section has no list to show and its verdict is the content — the roster's off-role check, for instance. It obeys the same fill rule as the card: clear does not tint, the green lives in the glyph and the words; cannot-evaluate keeps its dashed amber. Attention never uses this shape, because an attention finding always has items to list, and those belong in a card.

The same bar carries the empty-filter case that Comms.tsx already renders — "No thread matches this filter. 2 thread(s) were read from docs/team/messages.jsonl". It states the population it searched, so an empty channel never reads as a team with nothing to say. The prototype's data reaches every channel, so the state is not visible there; build it anyway.

Data tables
Every <table> goes in its own overflow-x: auto wrapper inside the card, with a min-width equal to the sum of its columns — the roster 820px, the workload table 680px. The card itself keeps overflow: hidden for its radius, and without the inner scroller that hidden silently amputates the rightmost columns: "Trigger / reason it is off" on the roster and "Static only" on the workload table — the two columns those screens exist to show. This is the .scroll wrapper the current Board.tsx and Team.tsx already put around every table; keep it.
Icons to add to icons.tsx

The v2 chrome uses five glyphs the existing set does not have. All stroke-based, 24×24 viewBox, stroke-width 2, round caps and joins, currentColor — same Icon wrapper as the rest. Nothing else is needed: the small state dots on kanban columns, role rows and the source list are CSS circles, not SVG.

ChevronDownIcon
m6 9 6 6 6-6. Trailing disclosure on the source chip and every dropdown.
SearchIcon
Circle r=7 at 11,11 plus a handle m20 20-3.5-3.5. The only thing left in the search field when it collapses to its 34px floor.
SelectorIcon
Opposed chevrons, up over down. Project switcher in the sidebar head — a two-way swap, not a one-way disclosure, so it must not reuse the chevron.
PanelIcon
Rounded rect with a vertical rule a third in — a page with a sidebar. The collapse toggle at the foot of the rail.
FilterIcon
A funnel as one closed path. Leads every filter dropdown — owner on Board, state on Team.
GroupIcon
Two stacked bands of unequal height — rows gathered into groups. Leads the group-by dropdown, so it matches its sibling filter control.

Icon rule: every element of a class gets one, or none of them do. Icon-bearing classes are status badges, message-kind chips, section headers, sidebar nav items, and toolbar dropdowns — including the group-by control, which is the same class as the filter beside it. Non-bearing classes are flag chips on ticket cards, metadata chips, and table cells.

5 · Chrome — sidebar, top bar, health

This replaces the old header and its eight wrapping pills. Three surfaces carry provenance, at three levels of loudness, and each states a different amount.

Sidebar
248px ↔ 60px
Project switcher, five nav items with attention counts, runtime line, collapse toggle. Collapsing to a 60px icon rail is not decoration: the Board needs 1326px for five columns, and the rail is what lets a 1440px laptop see all of them without horizontal scroll — see the arithmetic in §4. Nav item states are in §4. Rail state drops the labels and puts each in title, but the attention counts must survive it — reduced to a 14px red numeral pinned to the icon's top-right, with a 1.5px border in the sidebar fill so it reads against the glyph. The rail is the state an operator works the Board in, and with the health strip on Mission only, those counts are the sole persistent cross-screen signal that something needs them. Neutral counts (Team's roster size) drop with the labels; only attention counts are promoted.
Top bar
56px, sticky
Breadcrumb · search · connection pill · source chip · operator avatar. Shrink order is fixed and matters: the breadcrumb is flex:0 0 auto and never yields (the project segment truncates at 140px, the screen name never truncates); the right cluster is flex:0 0 auto and never yields; the search is the sole flexible item, flex:0 1 240px with a 34px floor and overflow:hidden, collapsing toward an icon-only box. Give any container in this bar min-width:0 and the shrink lands on the wrong element.
Health strip
Mission Control only
The full-width amber sentence naming the unreadable files renders on Mission Control and nowhere else. On the other four screens the bar chip carries the same fact in one chip. Rendering the strip on every screen makes it wallpaper within a week, and with journeys and verification routinely absent it would be permanently on. Nothing is hidden by this: the chip is present on every screen, in both states, always.
Source chip · 2 states · always present
all 8 sources 6 of 8 sources The healthy state is green and explicit — never absent. An empty slot where a verdict belongs is the failure this page exists to prevent. Both states open the same 8-row source panel.
Connection pill · 2 states
live · 14:22:06Z stream dropped · last read 14:22:06Z A dot that is always green is decoration. It earns its place only because App.tsx already detects EventSource.onerror — bind the amber state to it. Dashed, like every other "we cannot know" on this page: a page that stopped receiving updates is not reporting a problem, it is reporting that it can no longer tell you.
