HOW THIS BASELINE WAS PRODUCED, INCLUDING THE PART THAT WENT WRONG.

The first run of this suite reported 4/12. Three of those four PASSes were false:

  I-05  grepped approval-check.mjs for /merge[_-]?base|candidate_id/ and matched a CODE COMMENT
        plus an unrelated ancestor test.
  I-08  matched the word "reverse" inside a comment in trace.mjs.
  I-11  matched exactly one file — foundation-conformance.mjs ITSELF.
  I-10  observed one event after a duplicate submission and called it idempotency. It was the
        state machine refusing an illegal second claim. board.mjs has no idempotency support.

I-12 additionally reported the constitutional no-auto-publish constraint as VIOLATED, because the
checker names the forbidden commands in order to forbid them and then matched itself.

This is the same defect that broke the eval-manifest staleness check last session: a regex cannot
tell an ASSERTION from a CITATION. Every one of these was rewritten to run the system and observe
what it does, rather than read what its source says about itself. The remaining static checks
exclude self.

The lesson generalises past this file. A conformance suite is the one place a false PASS is worst,
because everything downstream is calibrated against it — and a suite that grades itself by grepping
its own repository will always find what it is looking for.
