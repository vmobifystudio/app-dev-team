# PR #47 review (fix/sprint-7): 16 findings

I found 16 problems. The full suite passes on macOS (`scripts/test.sh`: 2562 passed, 0 failed, about 15 minutes), so none of these are caught by the existing tests. The worst is PR47-1: the destructive-git hook no longer protects uncommitted edits to tracked studio files. V means I reproduced it by running it; R means I found it by reading. Fixtures are under `/private/tmp/claude-502/review47/`, with a clone of the branch at `.../clone`. I did not modify the repo.

---

**PR47-1 | High | V | `hooks/block-shared-tree-destructive-git.sh` (W7-9 `EXCL` block, the `DIRTY=` lines)**
- **What breaks:** the dirty-tree check now ignores every path in `operational-paths.txt`. Several of those are tracked on purpose: `docs/54-evidence/<bundle>.md` (QA bundles, which this PR makes tracked per R7-4), `docs/team/incidents.jsonl`, `memory.jsonl`, `docs/daily/`, `messages.jsonl`, `schedule.json`. An uncommitted edit to any of them no longer makes the tree "dirty", so the hook lets the command destroy it.
- **Repro:** fixture `hk2/`. Modify the tracked `docs/team/incidents.jsonl` and `docs/54-evidence/login-b12.md`, then run `git reset --hard`, `git checkout -- .` and `git stash`. The new hook exits 0 for all three; main's hook exits 2 for all three.
- **Fix:** exclude only paths that are untracked or ignored. For example, drop `EXCL` and instead filter `git status --porcelain` lines that start with `??` and match an operational path. Never skip a modified (`M`) tracked file.

**PR47-2 | High | V | `scripts/integration-branch.sh` `read_declared` (C7-5 anchored regex)**
- **What breaks:** declarations that resolved on main now exit 2 ("exists but declares no integration branch"):
  - `The integration branch is \`develop\`.` (listed as supported in the old comment)
  - `- Integration branch - develop` (hyphen separator dropped)
  - `1. Integration branch: develop` (numbered list)
  - `## Integration branch: develop` (heading)
- **Effect:** on existing projects, `closed`, `merged` risk and the wave all refuse, because the resolver is now fail-closed everywhere.
- **Repro:** fixture `ib/`, comparing old and new script output for each line.
- **Fix:** allow `#`, digits followed by `.`, and an ASCII `-` separator in the anchored prefix. Accept the `is` form only when it ends the line (`is \`x\`.$`) so prose like "is protected" still doesn't match.

**PR47-3 | High | V | `hooks/block-shared-tree-destructive-git.sh` `declared_for()`**
- **What breaks:** this is a consequence of PR47-2. When the script exits 2, the hook falls back to `main`, so the real integration branch loses its protection.
- **Repro:** a doc with `## Integration branch: develop`, on develop. `git merge --no-ff feat/x` and `git push origin feat/x:develop` both exit 0 on the new hook; main's hook blocks both (exit 2).
- **Fix:** on exit 2, protect every candidate (main, master, develop, and whatever the doc names) instead of only `main`. Also fix PR47-2.

**PR47-4 | Medium | V | `hooks/block-cross-worktree-write.sh` (R7-7 "own role" `case`)**
- **What breaks:** a developer whose cwd reset to the main checkout (the normal state, per R7-7) may write into any slot named `<its role>-N`. With several `ios-developer` instances running in parallel, which is the documented norm, they can write into each other's slots. That is exactly the collision this hook exists to stop (DR4-027).
- **Repro:** fixture `cw/`. An `ios-developer` with cwd = main checkout writing into `.agent-wt/ios-developer-2/...` gets exit 0. The same write from cwd `ios-developer-1` correctly gets exit 2.
- **Fix:** bind the slot to the agent. Look up the `agent_id` or ticket's lease in `worktree-slots.json`, or require the prompt's absolute slot path. Don't match on the role prefix.

**PR47-5 | Medium | V | `scripts/spawn-prompt.mjs` `composeIc` / `--retry` (rework not routed)**
- **What breaks:** after `move <ID> rework`, `compose` tells the developer to `git -C <slot> checkout -b feat/<ID>-<slug> main`, a new branch. It carries no wave FAIL/CONFLICT reason and doesn't mention the existing branch. `--retry` needs a REQUEST CHANGES verdict file, which a rework doesn't have.
- **Repro:** fixture `rw/`. Following the prompt gives a second branch, and `verified` is then refused with "several branches are named for T-1 … Delete the stale branch". `spawn-prompt.mjs` contains no handling for `rework` at all.
- **Fix:** when the last event is `rework`, compose a retry on the existing branch (check it out, rebase if it was a CONFLICT) and inline the `rework` event's detail as the task.

**PR47-6 | Medium | V | `hooks/contract-hooks.mjs` `guardGateWrites` `addRoot` (G7-12)**
- **What breaks:** the studio root is derived only from absolute or `~` spellings in the command. A relative target from a non-studio cwd still bypasses the guard.
- **Repro:** fixture `g12/`. From `outside/`, `rm -rf ../proj/docs/team/evidence` exits 0. The absolute spelling of the same path exits 2.
- **Fix:** also call `addRoot` on every path-like word that contains `/`, resolved against the cwd.

**PR47-7 | Medium | V | `scripts/lib/messages.mjs` `isRegistration`**
- **What breaks:** a registration is recognised by `channel === 'artifacts' && artifact`, and both of those are ordinary `send` flags. Any message can skip the MAX_CHAIN (4 roles) limit, and its `decision` won't close the thread.
- **Repro:** fixture `ms/`. `send --to <5 roles>` is REFUSED (chain_too_deep). The same send with `--channel artifacts --artifact docs/x.md` goes through.
- **Fix:** have `cmdArtifact` stamp a field that only it sets (e.g. `registration: true`), and have `cmdSend` reject `--channel artifacts`.

**PR47-8 | Medium | V | `scripts/lib/atomic.mjs` refusal text + messages.mjs/run-ledger.mjs migration**
- **What breaks:** main's `messages.mjs` lock was a directory, `messages.jsonl.lock/owner`, and main reaped it when its owner pid was dead. The new primitive can't read a directory and never reaps it. Every `send` then waits 30s and dies with "never delete it by hand", so that lock is stuck for good.
- **Also:** an empty, pid-less lockfile (holder killed between `openSync` and `writeFileSync`) is "left alone… the timeout surfaces it to a human" according to `reapIfStale`'s own comment. The new message forbids the only remedy.
- **Repro:** fixture `lk/`. A legacy dir lock with a dead pid gives `send` a 30.0s refusal.
- **Fix:** reap a legacy directory lock whose owner is dead. For pid-less locks older than N minutes, say what to do instead of "never delete".

**PR47-9 | Low-Med | V | destructive-git hook `SWEEP` `case` pattern**
- **What breaks:** two new false refusals in every studio main checkout:
  - `git clean -fd` (no `-x`) is now refused because the gitignored board log exists. `-fd` doesn't delete ignored files; main allowed this command.
  - `*stash*-u*` matches message text, so `git stash push -m update-ui` is refused.
- **Repro:** fixture `hk1/`. Both exit 2; main's hook exits 0 for `git clean -fd`.
- **Fix:** count ignored operational paths only for `-x`, `-X` or `stash -a`, and parse flags instead of glob-matching the whole command.

**PR47-10 | Low-Med | R | `scripts/ship-gate.sh` W7-5, `scripts/board-doctor.mjs`**
- **What breaks:** a log/anchor mismatch is downgraded from BLOCK to UNKNOWN, and board-doctor exits 2 instead of 1. That covers every mismatch kind, including `appended` (lines written without the CLI) and `rewritten` (same count, re-hashed history), which are tamper signals, not a moved project.
- **Wrong advice:** the message says `node board.mjs adopt`, but the new `adopt` refuses any mismatch without `--mismatch <kind>`.
- **Fix:** downgrade only for an absent anchor. Keep `appended`, `rewritten` and `deleted` as BLOCK, and print the `--mismatch` command that `checkAnchor` already builds.

**PR47-11 | Low | V | `scripts/wave-integrate.mjs` BASE vs `lib/integration.mjs` `integrationResolve` (G7-16)**
- **What breaks:** two resolvers disagree. In a fresh clone the board's base is `origin/develop`, but the wave uses the script's raw `develop`.
- **Repro:** fixture `fc/`. The wave dies with `the integration branch "develop" does not exist`, while the board resolves `origin/develop`.
- **Fix:** use `integrationResolve` in the wave. If only `origin/<name>` exists, say "create the local branch: `git branch <name> origin/<name>`".

**PR47-12 | Low | R | `scripts/runtime-gate.sh` W7-3**
- **What breaks:** the gate refuses in the main checkout unless HEAD equals the integration branch tip. `knowledge/git-workflow.md` documents `release/<version>` branches for develop-model projects, and `/app-ship` step 3b runs the runtime gate "on the candidate's HEAD". A release cut on a release branch is therefore always CANNOT EVALUATE.
- **Fix:** also accept HEAD that contains the integration tip (`merge-base --is-ancestor IB HEAD`), or accept a `release/*` branch.

**PR47-13 | Low | R | `scripts/lib/evidence.mjs` `journeyDeclarationGap`**
- **What breaks:** `UI_PLATFORMS` is matched exactly against each `platform` value. `project-profile.mjs` treats `platform` as free text (it uses `/\bweb\b/`), so values like `"ios+android"` or `"iOS, Android"` never trigger S7-5.
- **Fix:** word-match, the same way `project-profile.mjs` does.

**PR47-14 | Low | R | `scripts/lib/evidence.mjs:490` and `scripts/test.sh` `bm_evidence`**
- **What breaks:** any record with `produced_by === 'wave-integrate.mjs'` is exempt from `notIntegrated`, without checking that it ran on a wave branch (`integration/wave-N`) or that the wave landed.
- **Test impact:** the test helper now builds exactly that kind of record on the ticket's own unintegrated branch for every `qa_passed`, so every older QA test passes without going through the G7-2 check. Only the U2 tests exercise the real path.
- **Fix:** require `rec.branch` to match `integration/wave-*`, and have the helper produce QA evidence on the integration branch.

**PR47-15 | Low | R | printed commands and docs that no longer match the code**
- `corrected` now needs a token under `requireActorTokens`, but these print it without one: `commands/app-recover.md:70`, `scripts/dispatch-preflight.mjs:148` (also a relative `scripts/board.mjs` path), `scripts/merge-reconcile.mjs:174` (no `--by`). Each is refused once; the refusal does print the inline mint.
- `commands/app-recover.md` says run-doctor has "no `--root`", but this PR adds `--root` (S7-4).
- `composeVerify` routes a `QA-` ticket owned by qa-engineer and sitting at `qa` to `composeQaVerdict`, which prints `qa_passed`. That event isn't legal on `QA-` tickets (its legal events are `closed`, `verified`, `qa_failed`, `blocked`).
- **Fix:** add `&& !/^QA-/i.test(row.id)` to that check, and correct the texts above.

**PR47-16 | Low | R | `scripts/prompt-registry.mjs` / `scripts/team-doctor.mjs` (R7-13)**
- **What breaks:** the `template/*` entries are hashed only by `sync`. `prompt-registry check` validates fields only, and team-doctor checks role hashes only. An edit to `spawn-prompt.mjs` or `contract.mjs` without `sync` goes unnoticed, so "versioned" isn't enforced. The hashes match today.
- **Fix:** have team-doctor (or `check`) compare template entries' `content_hash` against the files.

**Checked and found sound:** the full `rework` round trip (merged → rework → done_reported → verified → review → approved → merged records the new `merged_head`); the `needs-approval` unblock gate on tickets born blocked with `add --status blocked --reason`; `adopt` locking; the `changedFiles` rename handling. Two portability notes:

- The new tests rely on test.sh's global git-identity fallback, which covers ubuntu's missing identity.
